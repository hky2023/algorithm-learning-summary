# 2026陕西西安邀请赛 A. North and South

## 题意简述

给定一个长度为 `n` 的数组 `a`。

一次操作选择一个偶数长度区间 `[l, r]`，并让：

- `a[l] -= 1`
- `a[l + 1] += 1`
- `a[l + 2] -= 1`
- `a[l + 3] += 1`
- ...
- 也就是从左到右交替减一、加一、减一、加一

问最少多少次操作能让整个数组所有数相等；如果无解输出 `-1`。

## 第一层观察

### 1. 总和不变

一次操作对区间内的增减是交错的，而且区间长度为偶数，所以总改变量为 `0`。

因此如果最终所有数都变成同一个值 `T`，那么一定有：

`T = sum(a) / n`

如果总和不能被 `n` 整除，直接无解。

### 2. 单点角度只能得到必要条件

从位置本身看：

- `a[1]` 只可能增加，因为它如果被某次操作包含，必然是区间左端点，受到的是 `+1` 方向的补偿到前缀里
- `a[n]` 只可能减少

所以：

- 必须有 `a[1] <= T`
- 必须有 `a[n] >= T`

但这些只是必要条件，不足以算最少操作数。

## 为什么直接看 `a[i]` 不好做

如果定义每个位置离目标值的差：

`d[i] = T - a[i]`

那么一次操作会让这一段的 `d` 变成：

`+1, -1, +1, -1, ...`

也就是一个交错变化。

这种作用在单点数组上不封闭，很难直接看出最优策略。

这时就应该考虑：

- 原操作是交错符号
- 是否能通过前缀和把交错消掉

## 核心建模：看前缀差值

设前缀和：

`S[i] = a[1] + a[2] + ... + a[i]`

如果最后所有数都变成 `T`，那么理想情况下前缀和应当是：

`i * T`

于是定义：

`b[i] = i * T - S[i]`，其中 `1 <= i < n`

含义是：第 `i` 个前缀距离目标前缀和还差多少。

注意只需要看前 `n - 1` 个前缀，因为第 `n` 个前缀就是总和，必然为 `0`。

## 一次操作对 `b` 的影响

考虑一次操作 `[l, r]`，区间长度为偶数。

原数组上是：

`-1, +1, -1, +1, ...`

把它累加到前缀里，会发现：

- 对 `i < l` 没影响
- 对 `l <= i < r`，只有某一类奇偶性的前缀会统一受到 `-1`
- 对 `i >= r`，因为整个区间净变化为 `0`，所以前缀影响又消失

更准确地说：

- 如果 `l` 是奇数，那么 `b[l], b[l+2], ..., b[r-1]` 全部减一
- 如果 `l` 是偶数，那么 `b[l], b[l+2], ..., b[r-1]` 全部减一

所以，题目被拆成了两个互不干扰的问题：

- 奇数下标的 `b`
- 偶数下标的 `b`

每次操作只会选其中一边的一段连续区间，整体减一。

## 无解条件的本质

因为每次操作只能让某些 `b[i]` 减一，不可能把一个负数拉回去。

因此必须满足：

`b[i] >= 0` 对所有 `1 <= i < n`

也就是：

`S[i] <= i * T`

这才是完整无解条件。

你最开始想到的：

- `a[1] <= T`
- `a[n] >= T`

其实只是这个条件在 `i = 1` 和 `i = n - 1` 的两个特例。

## 转化后的子问题

现在考虑一个普通问题：

给定一个非负数组 `c[1..m]`，一次操作可以选择一个连续区间 `[l, r]`，让这一段全部减一。

问最少多少次操作能让整个数组变成零。

答案是：

`c[1] + sum(max(0, c[i] - c[i-1]))`

也就是首项加所有正增量。

### 为什么是这个式子

把 `c` 看成高度图。

每次区间减一，相当于消掉一条水平线段。

那么：

- `c[1]` 表示第一列必须开启多少条线段
- 当 `c[i] > c[i-1]` 时，多出来的那部分高度必须新开线段
- 当 `c[i] <= c[i-1]` 时，不需要新开，之前的线段可以延续过来

所以最少次数就是所有“新开线段”的数量总和。

## 回到原题如何计算答案

把 `b[1..n-1]` 按下标奇偶拆成两列：

- 奇数位序列 `odd`
- 偶数位序列 `even`

答案就是：

- `cost(odd)`
- `+ cost(even)`

其中：

`cost(c) = c[1] + sum(max(0, c[i] - c[i-1]))`

## 算法流程

1. 读入数组，计算总和 `sum`
2. 如果 `sum % n != 0`，输出 `-1`
3. 令 `T = sum / n`
4. 扫一遍前缀和，计算每个 `b[i] = i * T - S[i]`
5. 如果某个 `b[i] < 0`，输出 `-1`
6. 按 `i` 的奇偶，把这些 `b[i]` 分到两个序列里
7. 分别统计首项加正增量和
8. 两部分相加即为答案

时间复杂度 `O(n)`，空间复杂度 `O(1)` 或 `O(n)` 都可以实现。

## 样例理解

例如：

`a = [1, 5, 1, 5]`

总和为 `12`，所以：

`T = 3`

前缀和：

- `S[1] = 1`
- `S[2] = 6`
- `S[3] = 7`

于是：

- `b[1] = 3 - 1 = 2`
- `b[2] = 6 - 6 = 0`
- `b[3] = 9 - 7 = 2`

拆开得到：

- 奇数位：`[2, 2]`
- 偶数位：`[0]`

所以答案为：

- 奇数位贡献 `2 + max(0, 2 - 2) = 2`
- 偶数位贡献 `0`

总答案就是 `2`。

## 这题最关键的经验

这题最难的地方不是实现，而是状态选取。

如果你一直盯着“每个数离平均数差多少”，会发现操作是交错加减，不好统计。

但如果你转而看“前缀距离目标前缀差多少”，交错结构就会塌成：

- 同奇偶
- 连续一段
- 整体减一

这种时候题目就基本做完了。

以后看到这种操作时，可以优先问自己两句：

1. 原操作在单点上是不是交错、震荡、不封闭？
2. 做前缀和之后，它会不会变成连续区间的统一修改？

如果答案是会，那大概率就该往前缀和建模上走。
